# Tuesday, Nov 17 — SEC EDGAR extract (2 hours)

**Goal:** `extract/` can pull company info and fundamentals for the S&P 500 from SEC EDGAR and write them as raw files under `data/raw/sec_edgar/<run_date>/`. Re-running the same day overwrites that day's files.

Endpoints (checked today, all return 200 with a User-Agent header):
- Company info: `https://data.sec.gov/submissions/CIK##########.json` (~28 KB for AAPL: name, SIC, tickers, exchanges, fiscal year end, state, addresses, recent filings)
- Fundamentals: `https://data.sec.gov/api/xbrl/companyfacts/CIK##########.json` (~280 KB for AAPL: every XBRL fact, e.g. `us-gaap/NetIncomeLoss` → `{start, end, val, fy, fp, form, filed, frame}`)
- SEC rules: a `User-Agent` with a contact email is required, max **10 requests/second**. Docs: https://www.sec.gov/search-filings/edgar-application-programming-interfaces

### Decisions (made Tue 0:00–0:20)
1. **Scope → everything.** Land the full companyfacts response; pick tags in dbt staging. Reason: extract stays simple (true ELT), and a new metric later needs no re-extract.
2. **Format → JSON Lines, responses unchanged.** One line per company: `submissions.jsonl`, `companyfacts.jsonl`. Reason: raw is exactly what SEC sent, Spark reads JSONL natively, and we avoid ~1,000 small files.
3. **Layout →** `data/raw/sec_edgar/<run_date>/submissions.jsonl` + `companyfacts.jsonl` (follows from 2).
4. **User-Agent → `SEC_USER_AGENT` in a git-ignored `.env`**, read from the environment; the script fails fast if it's missing. Same pattern for the FRED key and GitHub Actions secrets later.
5. **Backfill vs daily on the same date → decide in week 5** when scheduled daily runs start.
6. **Compression → gzip (`.jsonl.gz`)**, decided after the 3-company test. companyfacts is ~4 MB per company uncompressed (the 280 KB measured earlier was the gzipped transfer size), so ~2 GB for 500 companies; gzip is 15× smaller (~140 MB). Spark reads `.jsonl.gz` natively.
7. **Where raw data lives → Databricks.** No market data should stay on the PC. Development stays local, but each extract run is uploaded ("dumped") to a Databricks Volume, and local `data/raw/` is deleted at the end of each day. Upload step planned for Wed; L stage still starts Sun (week 2).

Largest records: MetLife companyfacts 10.4 MB, JPMorgan submissions 5.1 MB.
- Peak memory (3-company run): 168 MB, of which 108 MB is imports. Streaming keeps memory bound to the largest single record.
- Spark 3.5 reads `submissions.jsonl.gz` fine (500 rows, 24 columns).
- **Spark can't infer a schema for `companyfacts`:** `[COLUMN_ALREADY_EXISTS] employee`. XBRL tag and unit names are JSON *keys*, so inference turns them into struct fields (8,880 distinct tags, 497 units across 500 companies), and some units differ only by case (`Hotel`/`hotel`, `USD/Decimal`/`USD/decimal`). Spark is case-insensitive by default, so they collide. → L-stage decision for Sunday.

### Notes for later
- **dbt:** `cik` is a 10-digit string in submissions (`"0000320193"`) but an integer in companyfacts (`320193`). Normalize with `lpad(cast(cik as string), 10, '0')` before joining.
- Berkshire's submissions list both `BRK-B` and `BRK-A`; one CIK can map to several tickers.
