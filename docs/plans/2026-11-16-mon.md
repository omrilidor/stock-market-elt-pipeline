# Monday, Nov 16 — yfinance extract script (2 hours)

**Goal:** `extract/` can pull daily prices, splits and dividends for S&P 500 tickers from yfinance and write them as raw files under `data/raw/yfinance/<date>/`. Re-running the same day overwrites that day's files instead of duplicating them.

### Decisions (made Mon 0:00–0:20)
1. **Split-adjusted `Close` → option A.** Treat Yahoo `Close` as split-adjusted and apply only the dividend adjustment in dbt. Reason: it matches how Yahoo actually delivers the data, so there's less logic to get wrong.
2. **Raw format → Parquet** (new dependency `pyarrow`). Reason: typed columns (dates, floats), compressed, and Spark reads the schema from the file instead of guessing.
3. **Layout →** `data/raw/yfinance/<run_date>/prices.parquet`, `splits.parquet`, `dividends.parquet` (one file per dataset, not per ticker). Reason: 3 files instead of ~1,500 small ones; Spark handles a few larger files better.
4. **Window → one 5-year backfill, then daily runs with a ~10-day lookback.** The overlap catches late or corrected bars, and the dbt `merge` dedupes them. Restatements after splits are handled by re-running the backfill when needed.
5. **Notebook outputs → `nbstripout`** (new dev dependency, git filter). Re-commit `explore.ipynb` without outputs.

### Notes for later
- **dbt:** convert split/dividend timestamps to `America/New_York` *before* casting to date (`from_utc_timestamp`); otherwise a late-day event could land on the wrong day.
- **Open decision:** the backfill and a daily run on the same date both write `data/raw/yfinance/<run_date>/`, so the second run replaces the first. Options: a `--mode backfill|daily` subfolder, or never running both on one day.
- `write_run` stores timestamps as microseconds because Spark 3.5 can't read nanosecond Parquet timestamps.
