### Decisions made (Sun morning)
1. **Raw files for local dev:** (a) `extract/download_raw.py` pulls one run from the Volume. **No data kept on the PC:** it downloads into a temp folder inside the container (not the Windows bind mount), the load runs, and the temp folder is deleted automatically. The local lakehouse is throwaway (wiped at end of day, rebuilt in about a minute). Volume sizes checked today: yfinance 14.9 MB, FRED 5.7 MB, SEC 0.7 MB (2 companies only; the full S&P 500 companyfacts would be ~150+ MB). Rejected: Databricks Connect now (pulls the week-4 port forward, conflicts with `pyspark`, uses Free Edition quota).
2. **Data sample without downloading:** the SQL Statement Execution API from Postman (`POST /api/2.0/sql/statements`, warehouse `fe5eeddfce466f4d`, Bearer token from `.env`).
3. **Local storage:** registered tables, not path-only folders. Spark runs with `enableHiveSupport()` and a Derby metastore so tables outlive the session (dbt's session must see them). Data and metastore both live under `data/lakehouse/`, so wiping that folder resets everything together (no stale table entries). The Hive jars ship with PySpark, so no new dependency.
4. **Naming:** `bronze_<source>_<dataset>`, with the layer in the name and everything in one schema: locally `stock_market.bronze_yfinance_prices`, on Databricks `workspace.stock_market.bronze_yfinance_prices`.
5. **Idempotency + partitioning:** add `run_date` (from the folder name), write with `replaceWhere run_date = '<date>'`, `partitionBy("run_date")`. No MERGE in bronze (dedup by business key is dbt's job).
6. **Lineage (`_source_file`):** record the **Volume path** (e.g. `/Volumes/workspace/stock_market/raw/yfinance/2026-11-16/prices.parquet`), passed into `add_metadata` and set with `F.lit(...)`, not `_metadata.file_path`, which locally would record the deleted temp folder. One DataFrame = one file, so a constant is exact, and local and Databricks record the same path.
